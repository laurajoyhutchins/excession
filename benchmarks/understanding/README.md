# First code-understanding pilot

**This is an experiment in understanding software, not in recovering more SCIP
references.**

[Study manifest](study.json) freezes four questions before either retrieval
arm was run: three about SQLite's WAL locking, rollback-journal corruption and
B-tree commit phases at commit
`bcbbcee64ee7edd0b9883029da7251f9af1745d2`, plus one about Requests'
redirect authentication at
`3c7baaa05ab4aa49cc819ce3a819d260de19c157`.

The answer keys were hand-authored from primary upstream source, with exact
phrase anchors. They are **provisional, awaiting an independent reviewer**.
These source lines are not generated by SCIP, Excession or the benchmark
runner. The runner verifies the literal anchors against original Git objects
and refuses stale or missing source instead of inventing replacements.

## Stage 0: verify source and compare candidate reading lists

```sh
python3 -m unittest discover -s tests -p test_code_understanding_pilot.py -v
python3 benchmarks/understanding/pilot.py \
  --manifest benchmarks/understanding/study.json \
  --bin core/target/release/excession \
  --out /tmp/understanding-pilot
```

The runner fetches exact upstream commits into temporary detached checkouts,
validates source answer-key anchors against Git objects and compares:

**Pre-change control:** run 44099259305, Excession 5/7 preregistered
implementation/test paths and Git-only 6/7. The missing SQLite Tcl test
sources are an explicit negative result. Do not change that baseline or
present a post-change run against the same questions as held-out evidence.
Use these cases for *regression testing*, then evaluate changes on new,
preselected questions with independently reviewed answers.

- **Git-only:** ordinary `git grep -l -i -F` using distinct non-stopword
  terms from the same user question, ranked by number of matched terms and
  Git-path tie-break. It is a *deliberately modest Git search*, not a language
  server or a capable coding agent.
- **Excession:** the real compiled Rust `agent locate` with the identical
  question, 12-item budget and the source-first `reading_plan`. It uses a
  cold or warm external cache as reported and explicitly increases its
  file-size budget to 8 MiB. It is not a substitute for source reading.

Both arms' candidate file sets are compared with the independently authored
implementation/test path list. Output includes exact Git commit/tree,
source anchor locations, selected paths, missed paths, configuration, costs,
coverage and per-arm failures. The report is **retrieval diagnostic only**.
Paths omitted because of a source-extension limitation, budget, unsupported
configuration or parser failure stay missing, never inferred as absent
behavior. Index setup and processing are included in Excession cost.

A source path hit cannot establish the task was understood. No quantitative
claim of better agent performance follows from this stage, even if Excession
wins the retrieval proxy.

## Stage 1: blinded agent answer study

To establish genuine code comprehension, an independent reviewer must first
validate or correct the frozen source rubrics *without consulting either arm's
output*. Then run the same pinned model and reasoning budget against separate,
isolated checkouts:

1. **Baseline:** Git plus the usual code reader and language-server tools.
2. **Excession:** the exact same tools, plus `agent locate`, investigations
   and their source-bound evidence. No extra hidden source access.

The assignments must present only the question, commit and allowed interface,
**not the source answer key**. Randomize the sequence of arms and questions,
reset model context between trials, avoid public test-answer leakage, and
retain command logs, files/bytes inspected, tool calls, elapsed time and
token usage when genuinely reported.

Require answers to address each rubric fact, explain control/data/state
behavior with exact file/line citations, and state important assumptions,
counterexamples and unknowns. Human reviewers, blinded to the arm, score
claim correctness and each citation by inspecting original source; mark
unsupported or fabricated conclusions separately. Report missing responses,
abstentions, unmeasured usage and API/tool errors in the denominator. Do not
silently classify them as successes or zero-cost runs.

The real outcome questions are:

- Does Excession improve **correct source-supported behavioral explanations**?
- Does it help agents identify negative paths, tests and preservation
  obligations that baseline agents miss?
- Does it reduce *total* effort, including index preparation?
- Does it introduce false confidence by dressing a lexical candidate or SCIP
  symbol occurrence as a verified behavior?

**Status:** Stage 0 harness exists. Stage 1 agent executions and independently
adjudicated results have **not** been performed by this code. GitHub Actions
does not call a model, run SQLite or Requests, or assert behavioral truth.
